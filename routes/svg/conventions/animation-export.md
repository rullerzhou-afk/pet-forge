# SVG 动画导出与成品检查

把可交互 SVG 导出为 GIF、APNG、其他帧动画或展示短片时使用。本文给出工作方法，不提供通用录制器；控制器、浏览器和编码工具按项目现有环境选择。

## 先确定要交付的动作

控制器支持一个动作，不代表导出的时间线实际播放了它。导出前把用户要求对应到可见的动作区间：

| 要展示的内容 | 时间线中要确认什么 | 成品中要看什么 |
| --- | --- | --- |
| 眨眼 | 眼睛开合确实到达闭合再恢复 | 正常速度能读出闭眼，未被抽帧抹掉 |
| 嘴巴开合 | 开口参数发生变化，有需要的闭嘴停留 | 解码后的嘴型确实变化，而非一直张嘴 |
| 附属结构与毛发跟随 | 附属部件和毛片的运动均被驱动 | 毛尖可见，连接未裂，回弹未被提前截断 |
| 一次性动作的回程 | 进入、保持、回程各自有定义 | 回程不是末帧直接跳回首帧 |

用户要“完整动效”却没有逐项列出时，默认所有已做过并获认可的动作都要在成品里被看见；先列出清单给用户核对，再导出。动作已出现却难以看清时，先查取景、遮挡、停留和节奏；不要只增加帧率。

## 从真实控制器生成帧

使用最终预览所用的角色、控制器和动作输入，避免另写一条“看起来相似”的导出动画。保存来源版本或哈希、取景、输入事件、帧时间与编码参数，便于重建。

先分清控制器能否直接求任意时刻：

- 纯时间函数可以按目标时间求姿态；仍要应用完整的变形与合成顺序。
- 弹簧、惯性、随机待机和事件状态机依赖历史。不能只把时间设成 `t` 就假定得到正确姿态。
- 对有状态控制器，先重置到已知状态，固定随机种子和事件序列，再按稳定的时间步进推进到目标时刻。
- 随机访问某一帧时，从初态或包含全部内部状态的快照重放；只恢复可见角度会遗漏速度、冷却时间等状态。
- 模拟步长与输出帧间隔可以不同。按控制器适合的子步推进，再在输出时间采样；不要由机器截图快慢决定模拟速度。

导出期间只保留一个动作时钟。关闭自动 `requestAnimationFrame` 调度或使用项目已有的录制入口，避免实时循环和录制循环重复推进同一控制器。

浏览器截图前等待所需字体、图片及页面就绪，并确保当前姿态已经写入、完成绘制。导出 SVG 再栅格化时，要确认 CSS、渐变、裁切、字体和外部资源也被带入；静态栅格器不会代替浏览器执行原控制器。

固定时钟导出和实时录屏的分工见 [validation-runbook.md](validation-runbook.md) §7。实时录制要保存实际采样时间，不把不均匀捕获的帧当作等间隔播放；跳过等待、加首尾停顿或改成慢放时，在文件名或说明里标明，不称为原速完整过程。

## 先保留透明帧与时序

优先保留带 alpha 的 PNG 帧和每帧持续时间，再按目标格式编码。源帧与时序是后续换格式、调尺寸、查编码问题的依据。

透明导出的棋盘格只放在预览容器，不画进素材；检查是否有 `flatten`、不透明页面底色或截图选项把透明背景合并掉。

取景按整个动作的可见范围确定。需要近景时也检查最高耳尖、最远尾尖和毛发回弹，不能只用中性姿态裁图。相同动作的前后对照使用相同画幅和缩放。

记录至少应能回答：

- 哪份素材、哪套控制器与输入产生了这些帧；
- 逻辑时长、采样时间、每帧持续时间和预期循环方式；
- 输出尺寸、裁切范围、alpha 处理和编码配置；
- 成品文件的版本或校验值，以及哪些目标端实际播放过。

## 编码格式决定检查方法

| 格式 | 需要接受或核对的边界 |
| --- | --- |
| GIF | 使用调色板和透明索引，透明度为二值，不能保存 RGBA 的半透明毛边。帧延迟以百分之一秒计，取 ≥ 2 的整数（≤ 1 会被主流浏览器当作约 100ms 播放，动画突然变慢）；核对量化后的总时长和节奏。有透明且在移动的内容时，disposal 必须用“恢复背景”（2）；用 0 或 1 时上一帧会从本帧的透明处透出来，留下拖影，每帧输出整帧也挡不住。 |
| APNG | 可以保留完整 alpha；仍需核对实际颜色类型、位深、帧时长以及帧的 blend/dispose 设置。使用 APNG 扩展名不保证工具没有先量化颜色或 alpha。 |
| 其他格式 | 按目标播放器、编码器设置核对 alpha、色彩、时长精度与循环支持；不要套用 GIF 的透明阈值或时序结论。 |

GIF 的软边可以选择透明阈值、抖动或针对指定底色处理，各自会改变边缘观感。需要在多种底色保留细腻半透明边缘时，应评估支持 alpha 的格式；用户已指定 GIF 时，交付符合其格式边界的结果。

格式依据：[GIF89a Graphic Control Extension](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)、[PNG／APNG 规范](https://www.w3.org/TR/png-3/)。

## 重新解码成品

检查编码文件，而不仅是源 PNG 或编码命令退出码：

1. **基本属性**：读出尺寸、循环设置、各帧延迟及总时长。编码器可能合并相同帧，所以帧数变化本身不等于丢动作。GIF 可用 Pillow 快速读出每帧延迟和 disposal：

   ```python
   from PIL import Image
   im = Image.open("out.gif")
   for i in range(im.n_frames):
       im.seek(i)
       print(i, im.info.get("duration"), getattr(im, "disposal_method", None))
   ```

   Pillow 给出的 `duration` 单位是毫秒（20 表示 2 厘秒）。`disposal_method` 有疑问时，用另一个工具（如 `gifsicle --info`）交叉核对。
2. **显示帧**：按 blend/dispose 规则还原每个完整画面，不能把局部更新矩形当作完整帧比较。
3. **动作覆盖**：按成品时间回看前面的动作表，尤其是短暂闭眼、闭嘴、换画与接触瞬间。通道最小／最大值是线索，画面可读性仍需观看。
4. **透明边缘**：在深浅底上合成查看毛尖、阴影和移动过的空白区域；检查背景残影、实心区域缺失、边缘灰圈与颜色闪烁。
5. **节奏**：按正常速度连续播放，确认时间量化、重复帧合并或调色没有改变停顿、回弹和动作先后。

比较应遵守格式边界：无损 RGBA 管线可检查对应帧的 alpha 与颜色；GIF 应对照明确的透明阈值／调色策略，分别检查稳定实心区域、透明背景和软边允许误差。不要要求 GIF 与原 RGBA 每像素一致，也不要通过扩大容差掩盖大块残影。

## 循环检查的是跨周期连接

循环导出按 `t = i·T/N`（`i = 0 … N−1`）采样，**不含 `t = T`**：`t = T` 与 `t = 0` 是同一姿态，再编码一次会在每轮接点多停一帧。因此最后一个编码帧不应与第一帧相同。再检查周期边界的姿态、速度和必要的内部状态能否接续。

- 连续往返动作：观看最后几帧到下一轮前几帧，查突跳、停顿过长、速度断点和残留回弹。
- 有状态动作：检查跨周期后弹簧速度、随机事件或冷却是否按预期继续；若需要预热，明确预热和循环截取区间。
- 单向过渡：检查是否停在目标姿态或交给下一状态；重复审阅时跳回起点不等于已经制作回程。
- 为展示添加的首尾停顿应计入成品时长。重复编码同一个边界姿态可能制造多余停顿，不能把它当作无缝证明。

## 展示短片

对外展示或宣传用的短视频，不要直接把互动页固定机位录一遍。先排一版分镜（镜头顺序、景别、每段时长）给用户确认再渲染；景别、节奏和收尾方式由用户拍板，案例里一位用户的选择见 [SVG 实战复盘](../../../examples/svg-case-study-notes.md)。

技术要点：

- 近景和特写从矢量源按目标分辨率重新渲染，不放大低分辨率录屏；
- 没有配音时，角色张嘴的画面上必须有对应的对话气泡或字幕；特写里气泡会遮脸或被裁成半截时，换景别；
- 每个输入留出反应时间：先让观众看见触发（光标、点击），再看角色回应；
- MP4 等常见视频格式没有透明通道，先和用户定好底色或背景，再检查浅色毛发在该底色上的边缘。

## 交付时分别报告

用户要求可编辑来源时，一并交付实际使用的 SVG / HTML、控制器、必要资源、参数和重建说明；只给 RGBA 帧不能恢复参数化动画。按记录在独立目录打开或重建，检查来源没有依赖制作机器上的私有路径。

说明哪些动作已在成品中看见、透明和时序检查结果、实际播放过的目标，以及尚未验证的边界，记录方式见 [validation-runbook.md](validation-runbook.md) §9。动画源码改动后重新生成有关帧与成品。

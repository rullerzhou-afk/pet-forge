# Rig-first 变形合同

> 做任何手脚、尾巴、触角、脸部边缘、衣物边缘等会变形的部件前，先读这一页。

## 核心规则

不要直接拖生产 path 的原始控制点来做变形动画。

会变形的部件先建或复用一个小 rig：

1. 给语义锚点命名：根部、接触点、弯折点、末端、固定边。
2. 先让 0% path 和母版逐字一致，再做中间帧。
3. 先锁定用户/维护者认可的终点姿态，再调 easing 和二级动作。
4. 中间形态由 rig 生成，不靠临时点编辑凑。
5. 除非端点本身就是动作目标，否则端点先锁住。

刚体 transform 仍然是合法工具。一个部件本来就该整体平移、旋转、统一缩放时，可以直接用 transform。错误做法是拿整体 transform 或手拖控制点替代 deform。

## 造型、保持姿态、余动和表演分开

用户要求“拖动时自然、停住也对”时，先做可保持的姿态，不自动扩成一段表演：

- 造型基线：已认可的轮廓、色块、表情与连接关系；
- 保持姿态：由当前角度、开合等参数决定，停止拖动后仍应成立；
- 动态余动：速度、加速度或弹簧产生的滞后与回弹，停稳后衰减；
- 表演编排：何时转头、眨眼、停顿或甩尾，由时间线或交互行为安排。

例如耳根随当前耳角保持贴合，毛尖在移动时额外滞后。不能让姿态只靠速度项支撑：停住后速度归零，部件会退回中性轮廓、显得僵。姿态和余动的输入分开，再按需要叠加。多模块的时钟和写入顺序见 [motion-composition.md](motion-composition.md)。

## 毛发与配饰默认跟随

头部或身体一动，附近的毛发、配饰却纹丝不动，主动作再准也会显得僵，这类反馈很容易反复出现。所以：

- **新做**头部或身体动作时，默认包含跟随：先列出运动部位附近的毛片、发丝、衣角和挂饰，第一版就给它们加随姿态保持的形变和会衰减的余动；
- **修改已认可的动作**时，不擅自加跟随，只在交付说明里提出建议，由用户决定；
- 为防接缝而固定的区域尽量小：先量出底层离边缘多远，只钉真正会露缝的那一小段，不要整片锁死；
- 交付说明里写清哪些部位仍然不动。

## 运动中性帧

运动里的 `0` 位姿、`middle` 位姿和端点必须来自同一套几何模型。

不要让端点走锚点 rig，中间帧却切回 raw master path。两套 path 只要点顺序、曲率或边界不完全一致，过中线时就会 snap。

如果想保留静态母版，可以拆成两种语义：

- 静态展示：允许使用 raw master path；
- 运动中的中性位姿：继续使用同一套 rig 生成。

模块回到原稿对应的静态姿态并完全停稳退出后，可以恢复原始路径字符串以消除重建误差；前提是相关余动和过渡也已结束，且切回前后几何连续。停止拖动但仍保持非中性姿态时，继续保留该姿态的变形。角度刚好为零也不代表停稳：头回正时耳朵或毛尖可能还在摆。验收要同时覆盖运动过中线、停稳恢复和再次启动。

## 轴线变形

转头、转身、低头、承重这类动作，通常不是整块平移或整块旋转。

先定义一条语义轴，再用权重分配变形：

- 边界权重低，避免整块滑走；
- 轴线或中心区权重高，承担方向变化；
- 上下或前后可以有不同权重；
- 中间区域平滑过渡；
- `0%` 必须等于母版或已确认起点。

这条规则适用于脸部、身体、衣物边缘、尾巴、触角等可变形结构。

## 拓扑保持

闭合轮廓如果由几段 cubic / quadratic 组成，不要把 path 里的每个数字都当成轮廓点硬推。

更稳的做法：

- 找出主体语义锚点；
- 记录原始手柄比例或切线方向；
- 移动主体锚点；
- 成对重算控制手柄；
- 拼回同样的 path 拓扑和点顺序。

姿态可以变，拓扑不能乱。否则中间帧会出现尖点、坍塌、纸片化或无法插值。

## Dense warp 要求

部件 path 里常常同时有曲线和直线。只采样 `C` 曲线、不处理 `L` 段的 warp，会在混合路径上崩。

做 path warp 时：

- 结构化解析 path data；
- 尽量支持 `M`、`L`、`C`、`Q` 和 closepath；
- 先 dense 采样中线，再映射轮廓；
- 保留 winding 和 fill 行为；
- 信任动画前，先比对生成的 0% 帧是否等于源 path。

## 图层和接触关系

变形经常需要 helper layer。把 helper 当作 rig 的显式组成部分：

- 接触阴影、遮挡片、局部暗边要单独命名；
- helper layer 要 clip 到拥有它的身体或父表面；
- 不要把坏掉的肢体整条藏到身体后面；
- 如果 helper 只在单个姿势里验证过，标记为 pose-specific；做过渡动画前重新实看。

## 共享边界与自由端

先找出哪些路径共享同一段轮廓，例如浅色毛片与下层对比色底、衣物正面与侧面折层。它们需要沿同一变形场和同一变换顺序更新；只动上层会露出底色，即使没有透明孔洞也会像裂缝。

- 在共同坐标系计算连接，再换回各部件的局部坐标，避免父层旋转被重复应用；
- 根部随所属表面保持连接，自由端允许展收与惯性，中间用连续权重过渡；
- 为防露边而固定连接区，不等于锁死整片毛发或衣物；
- 色块、裁切和折面都检查，轮廓正确不保证内部颜色贴合；
- 比较共边几何，并在深浅背景下查看极端姿态与组合动作。透明孔洞检查不能替代有色接缝检查。

同源边界的回归检查与成片检查分别见 [validation-runbook.md](validation-runbook.md) 和 [animation-export.md](animation-export.md)。

## Transform-origin 归零

SVG 文件常带继承 CSS，例如 `transform-origin: center`。如果 rig 输出会写显式 `transform` 属性，先给被动画部件重置：

```css
transform-box: view-box;
transform-origin: 0 0;
```

先做这步再判断几何。错误 origin 会让正确 rig 看起来像飞走。

## 验收清单

锁定 rig 动画前检查：

- 0% 等于母版姿态；
- 100% 等于确认过的终点姿态；
- 循环或过渡连续播放多个完整周期无漂移；
- 关节没有尖角、坍塌、鼓包；
- 重要识别标志仍然可见；
- 常见浏览器缩放和目标 runtime/browser 都看过。

同一个问题连续两轮还以同样方式失败，就先停下，不要继续补症状。记录当前文件、现象、已试方案和边界，再重新审 rig 选择。

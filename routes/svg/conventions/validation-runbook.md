# SVG 验证 runbook

> 静帧截图不能代替动态或交互验收。按当前交付范围检查结构、行为和实际目标；未制作的动作不因此扩成新任务。

## 1. 先明确本次要看见什么

把用户要求的动作逐项写进 [动作验收表](../templates/action-acceptance.md)，小任务也可以直接在检查记录里列出。每项写清触发方式、可见变化和证据位置；控制器有接口，不代表交付时间线真的调用过它。

- 例如要求开口再闭口，就检查实际轨迹与画面是否覆盖两种状态，不能只验证“嘴巴控制器已加载”。
- 交互动作还要看多久出现、停留是否足以辨认、会被什么打断。关键展示动作若低概率抽中或总被用户操作取消，功能存在仍可能让人感觉没有。
- 随机行为用固定种子复现问题，再用正常操作检查出现频率；不要把单个种子的通过结果推广到所有过程。
- 动作范围、时长和次数依据本次目标填写，不套固定数量或幅度。

## 2. 结构先过

先确认文件能被解析：

- 裸 `.svg`：用 XML/SVG parser 检查标签闭合、命名空间、重复 `id`；
- `.svg.html`：用浏览器或 HTML parser 打开，确认 DOM 里存在目标 `<svg>`；
- 所有可动画部件有稳定 `id`；
- `viewBox` 能完整容纳动作幅度。

如果结构都不稳，不要先调动画。

## 3. 自包含检查

交付状态应该能独立运行。检查这些风险：

- 外部 `<script src>` / `<link rel="stylesheet">`；
- 跨文件 `<use href="other.svg#part">`；
- 必须联网才能加载的 image/font；
- runtime 不提供时会失败的 `fetch()`；
- 只在本机绝对路径存在的资源。

开发期 tuner 可以有外部依赖；canonical state 不可以。

## 4. 脚本可解析

含脚本的状态先做最小脚本检查：

- 浏览器 console 无 syntax error；
- 初始化函数可重复执行或有明确 guard；
- 没有未捕获 promise rejection；
- host bridge 缺失时能降级到默认动画；
- duration/readiness probe 返回稳定值。

这一步只证明“脚本能跑”，不证明“动画好看”。

## 5. 选择正确预览入口

不同文件形态用不同入口：

- `.svg.html`：直接用浏览器或 runtime 加载；
- 纯 `.svg`：可直接打开，但脚本、外链和安全策略可能和 runtime 不同；
- scripted SVG：用 `<object>`、iframe/webview 或内联预览壳验证；
- 需要本地资源的草稿：起一个本地静态 server，不要依赖 `file://` 行为。

如果直开文件和 runtime 表现不同，以 runtime 或与 runtime 等价的嵌入方式为准。

## 6. 检查整个过程和动作组合

连续播放多个完整周期，覆盖最长的次级动作；一次性动作检查从启动到收尾的完整过程。至少检查：

- 循环动作跨周期的姿态与运动是否衔接，一次性动作是否到达约定目标；
- 长周期元素是否越漂越远；
- blink、breath、secondary motion 是否全部同步抽搐；
- pointer-look 等脚本动画是否抖动；
- 关键识别部件是否被裁切、遮挡或滤镜污染。

端点通过不能替代中间过程：两端都无缝，途中仍可能露出被遮挡的颜色。按风险采样运动最快、遮挡变化最大和形态交接附近的帧，必要时放大检查。

交互或可中断动作还要覆盖启动、停止、换向、中途切换、重复触发、暂停后继续，以及回位后的再次启动。多控制器按 [动作合成](motion-composition.md) 核对组合顺序和写入归属，不只分别检查每个模块。

在已确认版本上新增模块时，做一次静止回归检查：新模块关闭或停稳退出后，已认可元素与已确认版一致（做法见 [动作合成](motion-composition.md) 的“合体检查”）。

单帧好看只能说明造型可用，不能说明状态可交付。GIF/APNG 等导出件还要检查编码后实际显示的帧序和时长，见 [动画导出](animation-export.md)。

## 7. 用重放定位，再检查实时播放

复杂组合或带状态的动画适合确定性重放；实时交付仍需正常打开检查。两种方式解决不同问题：

- **确定性重放**：等待资源和初始化完成后，用固定动作时钟和操作脚本重放；同一输入便于做前后对照、逐帧定位、轨迹检查和循环比较。
- **真实时钟交互**：正常打开最终页面，用实际指针、按钮或目标设备操作；检查异步加载、布局、CSS 过渡、事件命中、暂停恢复等固定步进可能跳过的行为。

尤其留意调试读数、气泡和控制面板是否随文字长短改变尺寸，把舞台推移或裁出窗口。录制时裁到角色区域，可能隐藏这类页面问题，也会漏掉浮在角色外的气泡；至少看一次正常窗口中的完整页面。

边缘检查按 [iteration.md](iteration.md) 第 4 步的评审页要求做：先用与角色反差大的背景，再切另一种各看一次。普通速度判断观感，慢放定位接缝，两者不能互相代替。模拟点击或触摸应记为模拟，不能写成真实设备通过。

## 8. 目标端复验

最后在用户实际会看到的目标里复验：

- runtime 映射是否指向正确文件；
- showcase / demo 是否引用 canonical state；
- HTTP 服务时 content type 是否合理；
- preview URL 和 production URL 是否为同一版本；
- 目标浏览器或 WebView 是否有 filter、mask、image 栅格化差异。

问题出现时先分层：源文件、嵌入方式、runtime 映射、部署缓存、目标端渲染。不要把所有现象都归因到动画本身。

## 9. 把结论绑定到产物与环境

本节是证据分层的唯一出处，其他文档链接到这里。用 [动作验收表](../templates/action-acceptance.md) 保存本次结论，按实际工作量裁剪字段：

- 被检查的源文件和输出文件，记录相对路径、提交或内容哈希；有未提交改动时，提交号不能唯一代表产物。
- 重现所需的命令或操作脚本、种子、输入和时钟方式，以及实际使用的浏览器/运行时与视口。
- 证据文件、通过范围和剩余限制。性能数据同时写采样动作、时段与环境，不推广成所有设备的预算保证。

源文件或输出改变后，旧结果仍属于旧版本；对受影响的动作和最终产物复验，不能只改记录日期。

分别记录结构检查、浏览器播放、用户视觉认可、编码后导出件、目标宿主/设备和已发布版本的状态。未执行就写 `NOT TESTED`，受阻写 `BLOCKED` 并说明条件；某项 `PASS` 不替代其他项，也不自动授权额外集成或发布。制作阶段与锁定关系见 [素材生命周期](../../../shared/asset-lifecycle.md)。

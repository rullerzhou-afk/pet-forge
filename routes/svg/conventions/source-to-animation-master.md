# 素材到动画母版约定

> 概念图解决“角色是谁”，初始 SVG 解决“像不像”，动画母版解决“能不能长期稳定地动”。

## 推荐链路

可复用链路：

```text
角色设定 / 概念图 / 参考 PNG
-> 角色拓扑盘点
   - 主体：只有头 / 头+身体 / 单主体 / 道具形
   - 脸部：眼睛 / 嘴巴 / 腮红 / 表情符号
   - 附属结构：手脚 / 耳朵 / 尾巴 / 触角 / 道具
   - 支撑关系：接地 / 悬浮 / 贴边 / 挂载
-> PNG→SVG 矢量化 / AI 或人工描图得到初始 SVG
-> 扁平化、调色、拆层、命名
-> 建立可计算角色系统（只为存在的结构建合同）
   - 脸部方向：左右 yaw / 上下 pitch / 视线 mixer
   - 主体与附属结构：主轴 / 骨骼点（如有）/ 接触点 / 重心或悬浮基准
   - 表情嘴巴（如有）：表情路径板 / 开口裁切 / 原嘴线收口
-> 写 transform-origin、层级和验证入口
-> 浏览器验证
-> 可继续做动画的 layered master
```

已有分层 SVG 可以跳过描图，先审计后继续动画。上面的链路用于补缺，不要求把已可用的结构拆掉重做。

## 已有分层稿与保真基线

- 保留来源包与已选静态画面；记录命名分组、隐藏表情、clip / mask / gradient 引用和已有控制器。
- 分清固定安放、局部姿态和整体位移的职责。动画写入姿态层，避免覆盖负责头身对位等用途的固定变换；锚点注明属于哪个局部坐标。
- 用目标尺寸和放大图分别检查识别特征与连接结构。比例、五官关系、毛束形状、配饰挂法等不能只靠 path 数量或文件大小评判。
- 已有结构能控制目标动作时直接复用；缺少的遮挡底形、语义分组或锚点再补。新控制器关闭时与已选基线对照。

PNG 概念图、模型 / 人工重绘 SVG、自动矢量追踪和已有分层稿是不同来源。重绘可能有干净的命名层，但仍需对照参考确认身份；自动描图可能接近轮廓，却没有可直接驱动的部位语义。可控制性与造型还原度分别检查，简化颜色或路径不能替代视觉认可。

概念图如果是角色动画设定板，会比普通插画更有价值。它不只是“长什么样”，还可能已经藏着后续 rig 的提示。重点看它是否包含：

- 三视图或方向参考；
- 动作示例；
- 可拆分部件提示；
- 头、身体、手脚、耳朵、尾巴等旋转轴意识；
- 表情和状态变化。

这些信息是制作策略，不是可以直接交付的资产。

## 描图和矢量化的定位

选择自动描图时，先拿到一张干净透明 PNG，再用 `routes/svg/tools/png2svg/` 的 `png2svg + vtracer` 转成初始 SVG。它适合低色数、边界干净、扁平卡通或图标类角色。

如果源素材是复杂概念图或角色设定板，也可以让强模型或人工先描出一版 SVG，用来快速抓比例、部件位置和主色区域。

两条入口的定位一样：把素材第一次转成可继续编辑的 SVG 角色，而不是把最终动画母版一次做完。

判断这一步是否成功，不看它能不能直接动画，而看它是否把概念图推进成“可编辑母版”：

- 大比例像；
- 头、身体、手脚、五官、配饰位置可用；
- 主色区域边界有基础；
- 文件是真 SVG，不是内嵌位图。

它不负责最终动画结构。不要因为矢量化或描图结果看起来已经像，就直接拿去做状态动画。

版本角色要分清：

- 比例源：解决“像不像”；
- 第一版分层动画母版：开始解决“能不能动”。

## 初始 SVG 的常见问题

初始描图 SVG 通常还是插画式文件：

- 渐变多，颜色依赖复杂；
- 图层顺序面向静态观感，不面向动画控制；
- `id` 不稳定或没有语义；
- `transform-origin` 没写清楚；
- 手、脚、耳朵、五官、配饰可能和主体混在一起；
- clip / mask / filter 没经过目标浏览器验证；
- 脸、身体、手脚只是 path，还不是可计算锚点系统。

它解决的是“像不像”，不是“能不能动”。

## 工程化成动画母版

进入动画母版前，先检查结构是否支持目标动作，再补缺失的部分。

先按 `layered-master.md` 把插画式 SVG 改成分层母版：稳定 `id`、稳定层级、明确 origin、可动画部件可单独控制。

额外注意：

- 渐变随变形是否漂移、接缝是否破坏原造型；仅在有问题时调整坐标或简化，不默认去掉已认可的材质；
- 在目标背景和桌面尺寸检查可读性，需要调色时保留已选色板供对照；
- 在浏览器里打开验证，不只信编辑器预览；
- 记录哪一版是比例源，哪一版开始是动画母版。

第一版动画母版不需要一次变完美，但必须能被后续 tuner 和状态文件稳定复制。

结构整理是为了让每个状态复用同一套边界、锚点和遮挡关系。扁平化、调色或减线是候选手段，不是把所有角色改成同一审美的要求。

## 描线取舍

保留已选角色的描线语言，按实际缩放、变形和遮挡决定如何处理边界。

概念图可用描线讲清部件和旋转轴。最终 SVG 可用 fill、clip、局部阴影或描线组合表达边界；需要的是各层运动时仍然连续。

小尺寸、透明背景和桌面窗口中的描线观感可能不同于静态设定图，应在目标尺寸查看再决定是否减线。

多个独立描边部件在动画里需注意：

- 双线；
- 断线；
- 圆头线头；
- 拼接缝；
- 额外 seam；
- clip 裁切后的脏边；
- 手进入身体或脸部转向时不该露出的内侧轮廓。

常见功能线包括：

- 眉毛；
- 嘴巴；
- 鼻口表情线；
- 少量必要的小部件边界。

发生双线或断口时，先核对共享轮廓、描边归属与裁切；是否减少描边按角色风格决定，不用统一去线掩盖错误的连接关系。

## 可计算角色系统

动画母版不是一张“整理干净的 SVG”，而是一套可计算角色系统。

建立系统前先做角色拓扑盘点。不要默认每个角色都有完整头、身体、手、脚、嘴巴。只有头的角色、软团角色、道具形角色和完整吉祥物，需要的合同不一样。

在同一个维度里并列判断这些合同：

- 脸部方向合同：有脸部方向需求时，说明脸部轮廓、浅色脸区、眼睛、鼻子、嘴、腮红、耳朵如何随 `yaw`、`pitch` 和 mixer 运动；
- 主体与附属结构合同：说明主体主轴、重心 / 悬浮基准在哪里；有手脚、尾巴、触角、道具时，再说明骨骼点、接触点和父级锚点；
- 表情嘴巴合同：有嘴巴或多表情需求时，说明表情路径板怎么复用，嘴巴是 path 替换、开口裁切，还是原嘴线收口。

进入多状态前，至少要回答：

- 角色边界是否能由锚点重建，而不是只靠 path 字符串；
- 角色实际存在的结构是否都有对应合同，没有的结构是否被明确跳过；
- 五官、腮红、耳朵、配饰或道具分别属于哪个运动平面 / 父级结构；
- 运动中性帧是否来自同一套模型。

如果这些问题答不上来，先不要扩展状态。继续做更多静态帧，只会增加后续返工面积。

## 验收清单

初始 SVG 升级成动画母版前检查：

- 概念图里的拆分和轴线信息已经被转成部件和锚点；
- 初始 SVG 里的渐变、clip、mask、filter 没有成为后续动画负担；
- 所有未来会动的部件都有稳定 `id`；
- 关键部件有明确 pivot / origin；
- 脸部主色边界、五官、腮红和耳朵可独立控制；
- 身体、手、脚、配饰可独立控制；
- 选定的描线与材质在变形、缩放和目标背景下保持可读；
- 浏览器直接打开后层级、颜色、遮挡都正常。

新角色动画开工前再问一遍：

- 角色边界是否可计算；
- 主体主轴、重心或悬浮基准在哪里；
- 如果有手脚、尾巴、触角、道具，它们的骨骼点、接触点和父级锚点在哪里；
- 如果有嘴巴或表情，嘴巴是 path 替换、遮罩开口，还是原嘴线收口；
- 如果有脸部方向，五官属于哪个运动平面；
- 中间帧是否来自同一套模型。

# APNG 分段生成、组装与速度选择

复杂桌宠动作不必强迫视频模型一次完成。把动作拆成语义清楚的片段，可以单独重生成失败部分，同时保留已经通过的部分。

本文件描述的是组装层。每个单独片段以及最终合成动作，仍然遵守 `loop-and-anchoring.md` 的 A / B / C 首尾关系，但它们可以属于不同类别：`X → M`、`M → Y` 这类首尾姿势不同的进入/退出子段按 C 类生成；`M → M` 的保持循环按 A 类生成；最终组装动作再按整体首尾和播放语义分类。不要把最终循环的 `Seamless loop` 文案直接套给其中的 C 类子段。

## 什么时候拆段

动作包含下列情况时，优先考虑拆段：

- 进入、保持、退出三个阶段；
- 展开道具、展示内容、收起道具；
- 从一个循环姿势过渡到另一个循环姿势；
- 一个片段已经合格，另一个片段仍反复变形；
- 中途出现道具、伙伴或特效实体，且需要稳定造型；
- 单条视频里动作太多，节奏或首尾关系难以控制。

段边界尽量选在姿态稳定、遮挡较少、接触关系清楚的画面。不要为了凑固定段数而拆分简单动作。

## 共同中间关键帧

相邻片段使用同一份中间关键帧文件：

```text
片段一：起始图 X → 中间图 M
片段二：中间图 M → 结束图 Y
```

`M` 应当是同一文件的同一份字节，不要重新导出一张看起来相同的图片。记录每张输入图的用途和哈希，避免后续混淆版本。

共同关键帧只约束生成输入，不证明成片接缝无缝。仍要检查片段一的实际最后帧与片段二的实际第一帧。

## 多图输入的提示词语义

提示词应直接说明输入图片的角色：

```text
图1是首帧，图2是尾帧。画面从图1的姿势开始，最终准确过渡到图2的姿势。
```

不要只写内部状态名、文件名或本机路径。模型未必知道这些名称代表什么。

如果某个道具只出现在图2，应从它第一次进入画面起就锁定身份：

```text
该道具从首次出现的那一帧起，就保持与图2完全相同的轮廓、填色、描边、内部结构和数量；不要先出现另一种造型再变成图2。
```

道具不必强制出现在每一张锚点图里，但至少应在一个相关锚点中清楚可见，或者另有一张道具参考图。文字约束不能替代视觉锚点，只能补充它。

## 用当前工具生成自定义片段

`routes/apng/tools/gen-video.js` 当前只接受 `routes/apng/prompts/template.js` 中已有的模板键，也没有通用的自定义片段 prompt 参数。因此：

- 片段语义正好对应现有模板条目时，可以直接使用该条目并用 `--image`、`--last-frame` 传入实际锚点；
- 自定义片段可以在生成服务的网页端或 API 端按本文 prompt 生成，再回到本仓库做抠图、组装与 APNG 重建；
- 在自己的项目副本中扩展 `ANIMATIONS` 也可以，但若改动本仓库的模板条目数量，需要同步更新 `scripts/validate.mjs` 的模板断言和相关说明。

不要为了通过 CLI 校验而套用动作含义不相符的模板键。

## 正向生成还是倒放

倒放是一种可选的剪辑手段，不是默认捷径，也不是禁用项。

适合倒放的片段通常具有这些特征：

- 动作在视觉上可逆；
- 没有明显的单向加速度或重量变化；
- 没有只朝一个方向运动的粒子、烟雾、拖尾；
- 表情和叙事在倒放后仍然合理；
- 用户接受复用同一段动作。

含有衣料惯性、自然行走、情绪变化、物体碰撞、液体或定向特效时，通常分别正向生成更自然。最终以连续播放效果为准。

## 只替换失败片段

一个片段失败时，保留已通过片段，重新生成受影响的部分。为了知道修正是否有效，优先一次改变一个真正相关的变量，例如：

- 道具身份描述；
- 固定不动的手或身体区域；
- 镜头约束；
- 动作幅度；
- 首尾关键帧。

这不是禁止同时修复多个已确认问题。问题彼此相关时，可以在同一轮一起修正，并记录改动内容。

## 拼接与接缝检查

先按原始速度直接拼接，不要用交叉淡化掩盖姿势或颜色不连续。逐帧检查：

- 接缝两侧的角色位置、比例和姿势；
- 手、眼睛、头发、衣袖和道具的连续性；
- 亮度、色相、饱和度和描边颜色；
- 是否存在重复帧或一段意外静止；
- alpha、SVG 特效和遮挡层是否使用同一帧时钟；
- 最终整条动画是否仍满足预期的 A / B / C 首尾关系。

采样图适合定位问题，不能代替连续播放验收。

本仓库当前没有通用的片段拼接脚本。可使用 `ffmpeg` 或等价工具连接编码参数兼容的片段，也可以先解码成帧序列，按确认的顺序合并后再构建 APNG。`rebuild_apng.py` 可以从 PNG 帧目录重建统一帧率的 APNG；更复杂的可变帧时长需要使用支持相应时间信息的编码工具。

## 速度选择

速度是独立的视觉决策。先确认动作和接缝，再按用户需要提供若干实际播放速度供比较。`1x / 1.5x / 2x` 只是常见示例，不是固定档位，也不限制方案数量。

比较时要播放完整组装动作，因为变速会同时改变停顿、接缝和情绪读感。选定后记录：

- 来源视频或帧序列；
- 来源哈希；
- 选定倍速或目标帧时长；
- 是否保留所有源帧；
- 最终循环次数语义。

比较同一来源的速度方案时，优先只修改帧时长，不把额外删帧混成第二个变量。MP4 观感比较可以先用播放器倍率，正式导出是否需要转码取决于容器和编码链；最终 APNG 的目标帧率、尺寸和颜色数属于独立的交付压缩决策。目标运行时对极短帧时长有钳制时，应在真实运行时再次验证。

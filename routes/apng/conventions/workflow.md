# APNG 路线工作流

> 从运行时需求、Codex 生图和关键帧规划开始，经过视频生成、分段组装、透明处理、矢量合成和实际运行验收。

## 管线总览

```text
[0. 核对运行时与状态]
   ↓
[1. 建立角色、姿势和道具参考]
   ↓  Codex 生图 / 编辑已有图 / 手绘 / 其他生成工具
[2. 定义首尾关系与片段计划]
   ↓  A/B/C + 共同中间关键帧
[3. 写 prompt]
   ↓
[4. 配置并生成视频]
   ↓
[5. 审核原片，局部重生成]
   ↓
[6. 拼接并选择播放速度]
   ↓
[7. 色键抠图与透明边缘处理]
   ↓
[8. SVG 精确效果 + 跨片段调色]
   ↓
[9. 锁定、运行时接入与发布]
```

每一阶段解决不同问题。生成成功不等于正式资产，具体阶段见 `shared/asset-lifecycle.md`。

## 第 0 步：核对真实目标

开始画图前先检查目标桌宠运行时：

- 实际使用哪些状态名；
- 每个状态是循环、一次性回归，还是状态间过渡；
- 窗口尺寸、可视边缘、贴边方向和裁切范围；
- 窗口移动由 host 完成，还是动画素材内部完成；
- mini、hover、sleep 等状态之间如何切换；
- 最终格式、尺寸、体积和播放次数要求。

`shared/state-map.md` 提供通用模板，不代表每个产品都必须实现相同数量或相同姿势。先看真实 runtime，再决定需要制作什么。

## 第 1 步：建立参考图与关键帧库

### 参考图的角色

不同图片承担不同职责：

- **角色身份参考**：锁定脸、比例、配色、服装、描边和材质；
- **状态锚点**：某个状态实际使用的首帧或尾帧；
- **共同中间关键帧**：连接两个生成片段；
- **道具参考**：锁定道具、伙伴或特效实体的设计；
- **姿势参考**：说明手掌朝向、肘部、肩膀、重心和接触关系。

一张主参考图不足以解决所有姿势。角色身份可以共享，但关键动作应有自己的视觉锚点。

### 使用 Codex 生图

当前 Codex 提供图像生成能力时，可以直接用于：

- 从文字创建角色概念图或身份参考；
- 基于已选图片补全身体和画布外区域；
- 只修改手势、表情、道具或指定肢体；
- 生成首帧、尾帧和共同中间关键帧；
- 生成若干构图或动作方案供用户比较；
- 创建带空白纸张、卷轴或面板的后期合成底图。

用户说“去生图”“再生成一版”或指定方案数量时，已经授权了该批次。直接按请求执行，不重复询问，也不附加固定张数或固定尝试次数。用户没有指定数量时，根据当前决策需要生成足够的一组；方向已经明确、无需比较时，一张也可以。

编辑已有图片前先查看输入，明确：

- 哪些识别特征必须保持；
- 这次只改变什么；
- 哪些区域必须不动；
- 画面需要为运行时裁切保留多少完整身体和留白；
- 背景色是否与角色和后续抠图兼容。

特殊手势连续生成仍不合理时，不要继续堆同义提示词。补充有权使用的真人照片、骨架草图、手势特写或带墙面/窗口边界的合成预览，再做图片编辑。

### 关键帧通过条件

- 角色身份与已选设定一致；
- 身体结构、手指和接触关系合理；
- 需要锁定的道具清楚可见，或另有道具参考；
- 构图适合目标运行时的裁切和贴边方式；
- 首尾帧之间存在可生成的动作路径；
- 需要准确文字或符号的表面保持空白。

保存实际图片文件、用途和版本关系。后续视频应引用这张已选图片，不要只根据文字重新创造一张“差不多”的图。

使用豆包 / Seedance 时，先按整套动画的最大运动范围选择画幅，再制作参考图。主参考图、各状态首尾帧和视频应保持同一比例、人物尺度、中心轴与脚底线；图片比例与请求比例不一致时可能被中心裁切。实际输出像素、输入限制与比例选择见 `doubao-video-output.md`。

## 第 2 步：定义动作、首尾关系和片段

先按 `loop-and-anchoring.md` 判断：

- A：循环，首帧与尾帧姿势相同；
- B：一次性回归，动作后回到开始姿势；
- C：一次性过渡，结束在另一种姿势。

复杂动作按 `segment-assembly.md` 拆分。相邻片段使用同一份中间关键帧文件，一段失败时只替换受影响片段。

## 第 3 步：写 prompt

模板见 `routes/apng/prompts/template.js`。建议把不同职责分开写：

```text
[IDENTITY]       角色身份、配色、比例、材质和描边
[INPUT ROLES]    图1是首帧，图2是尾帧，各自是什么姿势
[MOTION]         动作、节奏、幅度和顺序
[LOCKED REGIONS] 必须不动的身体区域、手、镜头或道具
[PROP CONTRACT]  道具数量、轮廓、配色、纹样、接触与遮挡
[CAMERA / BG]    镜头、构图和色键背景
[NEGATIVE]       针对已知失败模式的否定约束
```

动作描述应具体到可观察行为。不要加入模型无法理解的内部文件名，也不要用大量互相冲突的形容词。

当动作需要手时，不要同时写 `NO hands`。应描述正确的手：哪只手、掌心或手背朝向、手指数、肘部方向、握持位置，以及另一只手是否锁定不动。

prompt 长度没有通用上下限。写到足以锁定身份、动作和禁区即可；如果模型抓不住重点，优先整理结构和删除矛盾，而不是追求固定词数。

## 第 4 步：配置并生成视频

工具用法见 `routes/apng/tools/README.md`。示例：

```powershell
node gen-video.js idle-dozing \
  --image reference/main-ref.png \
  --last-frame reference/main-ref.png \
  --resolution 1080p \
  --ratio 1:1 \
  --camera-fixed \
  --api doubao
```

`1080p` 是清晰度档位，实际像素由它与 `ratio` 共同决定。不要用任意比例的参考图再依赖接口改画幅；正式生成前按 `doubao-video-output.md` 核对当前模型规格。

选择生成服务时关注它是否支持需要的首尾帧能力、当前成本、排队情况和输出稳定性。外部服务会消耗额度；用户已明确要求具体生成批次时直接执行该批次，不静默增加额外尝试。提交结果不确定时，先查询已有任务状态，避免重复扣费。

失败次数没有通用预算。是否继续抽卡由问题性质、成本、已获授权和用户反馈共同决定。

## 第 5 步：审核原片

连续播放原片，并按动作实际依赖逐帧检查：

- 角色身份、比例和颜色；
- 手指数量、手掌朝向、肘部和肩膀；
- 固定区域是否漂移；
- 道具数量、造型和接触点；
- 眼睛是否按状态保持睁开、闭合或眨眼；
- 是否增生尾巴、辫子、手、云朵或背景物；
- 镜头是否意外平移、缩放或旋转；
- 背景是否干净，是否混入速度线、地面或阴影；
- 实际首尾帧、停顿和重复帧；
- 动作幅度和节奏。

### 判断重生成还是后处理

通常需要重生成：

- 人体或主体结构错误；
- 角色或道具身份改变；
- 错误遮挡、穿模或多余肢体；
- 镜头和构图破坏动作；
- 核心动作没有执行。

通常适合后处理：

- 需要准确显示的文字和符号；
- 可控粒子、发光和提示线；
- 可测量的停顿帧或播放速度；
- 色键、透明边缘和跨片段色差；
- 可以逐帧定位的矢量跟随。

这些是判断依据，不是绝对禁止。以保真度、时间和用户选择为准。

## 第 6 步：组装与速度

按 `segment-assembly.md` 拼接片段，先检查实际接缝，再比较速度。速度档位按当前动作需要提供，常见的多个倍率只是示例，不是数量限制。

变速后再次检查：

- 接缝是否更明显；
- 呼吸、眨眼和停顿是否自然；
- SVG 层是否仍对齐；
- 运行时是否钳制过短帧时长。

## 第 7 步：透明处理

`chroma_key.py` 示例：

```powershell
py chroma_key.py output/idle/raw.mp4 output/idle/result.apng --plays 0 --key-color "#00B140"
```

macOS / Linux 通常使用 `python3`。`--plays 0` 表示无限循环，`--plays 1` 表示播放一次。最终值来自状态的 `loop` 语义，不从文件名或首尾锚点猜测。

色键选择、背景采样、半透明区域和跨片段调色见 `chroma-and-edges.md`。当前脚本的硬遮罩、软边和去溢色都使用请求的 `--key-color`，不会额外套一层绿色遮罩；仍需用代表性帧调节容差并检查细节侵蚀。

按需使用：

- `fix_gray_bleed.py`：边缘灰污；
- `check_dark.py`：暗部泄漏检查；
- `rebuild_apng.py`：尺寸、颜色数和帧时长重建。

## 第 8 步：SVG 精确合成与统一调色

需要准确文字、符号、粒子、声波或脚步弧光时，按 `hybrid-overlays.md` 使用 SVG 效果层。矢量层必须根据成片的实际锚点和遮挡逐帧跟随，并与人物层共用同一帧时钟。

多片段、多状态应对齐同一份已锁定角色基准，而不是只让每段内部自洽。只做颜色处理时保持 alpha、帧时长和 SVG 数据不变。

## 第 9 步：锁定、运行时接入与发布

按 `shared/asset-lifecycle.md` 记录已选关键帧、已确认原片、透明人物层、完整合成和锁定资产。原始媒体是否进入版本控制由目标仓库政策决定，不自动提交。

接入后在真实运行时检查：

- 状态映射和播放次数；
- 真实尺寸、窗口边缘和裁切；
- host 位移与素材内部动作是否重复；
- 状态切换和循环接缝；
- 文件体积和加载性能。

部署或发布完成后读取实际目标，不用本地文件存在或 HTTP 状态代替视觉验收。

## 成本与授权原则

- 用户对具体生图、生视频或重试批次的指令，就是该范围的授权；
- 不重复请求已经给出的许可；
- 不设置固定图片数、固定尝试数或固定状态数；
- 不静默扩大付费批次，不在结果不确定时重复提交；
- 用户已改变方向时，停止旧方向的新增生成，保留已有证据供回看；
- 审美结论由用户决定，工具检查只证明技术属性。

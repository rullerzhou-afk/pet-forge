# 色键、透明边缘与跨片段调色

本文是 pet-forge 色键与边缘处理的规范源；其他入口只保留摘要和指向，工具能力变化时以这里为准。

抠图质量取决于角色色域、实际背景、半透明像素和后续显示背景。不要把“绿幕”当成唯一方案，也不要把 prompt 中写下的颜色当成视频的真实背景色。

## 选择色键颜色

先检查角色、道具和特效的主要颜色，再选择与它们重叠最少的背景色。

- 角色包含大面积绿色或青色时，应避开绿幕；
- 角色包含大面积粉色或紫色时，应避开洋红背景；
- 发光、烟雾和半透明拖尾也属于需要保留的色域；
- 参考图、视频提示词和抠图参数应使用同一色键约定。

色键颜色由素材决定，不存在对所有角色都最好的固定颜色。

## 当前工具的能力边界

`routes/apng/tools/chroma_key.py` 支持任意 `#RRGGBB` 色键：

- 硬背景判断使用像素与 `--key-color` 的 RGB 欧氏距离；
- 软边 alpha 由 `--tolerance` 到外层边缘带的距离计算；
- 去溢色根据同一个 `key_rgb` 反推出前景色，不额外删除绿色。
- 当前脚本随后会无条件对 alpha 使用一次 3×3 `MinFilter`，相当于统一向内收约 1px，细线和发丝必须复核；当前没有关闭该步骤的命令行开关。

默认转换参数是 `--fps 8 --height 200 --max-colors 192`。脚本按输入视频约 24fps 的假设抽取目标帧，再统一缩放和量化，因此默认结果是有损、偏预览用途的起点，不代表所有运行时的定稿规格。正式导出应按源视频和目标运行时显式选择 `--fps`、`--height` 与 `--max-colors`，并比较转换前后动作、边缘和体积。

`fix_gray_bleed.py` 和 `rebuild_apng.py` 也会重新缩放和量化，并共享 200px / 192 色默认值；`rebuild_apng.py` 还默认 8fps。若前一步已经选定更高规格，后处理命令必须重复传入同一组 `--height`、`--max-colors` 和适用的 `--fps`，避免无意降级。

工具会用一组 `--key-color` 和 `--tolerance` 处理整段视频，不会自动为每一帧估计不同背景。处理前仍需抽查代表性帧；若背景随时间或片段明显漂移，可分段使用不同参数，或换用支持逐帧、自适应采样的抠图流程。

容差过大或上述统一形态学处理仍可能侵蚀发丝、薄纱、描边和内部小孔。任意色键支持解决的是“按哪种颜色抠”，不代替边缘验收。

## 采样实际背景

生成视频中的背景可能随时间漂移。处理前应检查多个时间点和画面区域：

- 四角和远离角色的位置；
- 角色边缘附近；
- 首帧、尾帧和动作幅度最大的帧；
- 不同片段的接缝附近。

prompt 里的十六进制颜色只是生成要求。抠图参数应以输出视频的实际像素为准。必要时按片段调整，或建立逐帧、自适应流程，而不是让整条视频共用一个未经验证的采样值。

## 半透明内容

发梢、薄纱、光晕、烟雾、拖尾和发光粒子可能与背景混色。它们不能简单按不透明主体或纯背景处理。

检查时区分：

- 确定属于背景的连通区域；
- 与主体边缘相连的半透明美术；
- 被角色或道具包围的内部空洞；
- 被画布边缘截断的主体部分；
- 原图自带的描边。

当前脚本已经包含一次固定 alpha 内收。不要在不了解现有结果时继续叠加膨胀、腐蚀或模糊；若固定内收损伤造型，应调整工具或换用可控的抠图流程。

## 边缘验收

透明结果应在能够暴露边缘问题的背景上连续播放检查，例如：

- 浅色背景；
- 深色背景；
- 透明棋盘背景；
- 实际桌宠运行时背景或具有代表性的桌面截图。

同时检查画布四边是否形成直线切口，角色内部是否出现错误透明洞，光效是否被当成背景清除。静态截图只能辅助定位，最终以连续播放为准。

## 跨片段和跨状态调色

“单个片段内部颜色稳定”不等于整套主题颜色一致。应先选定一份已确认的角色参考或已锁定状态作为颜色基准，再比较所有片段：

- 肤色、毛色或主体色；
- 头发、衣物和配饰；
- 描边颜色与亮度；
- 道具材质；
- 首尾帧和片段接缝。

段内漂移可以沿时间线平滑补偿；接缝两侧可以使用不同参数。只做调色时保持 alpha、帧时长和矢量层原字节不变，并保留调色前后对照。

跨片段调色属于正式资产阶段。生成候选的轻微差异可以先留到统一处理，不必因此重新生成一个动作结构已经正确的视频。

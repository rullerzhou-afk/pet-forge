# 桌宠素材生命周期与验收

桌宠制作会产生多种用途不同的文件。明确它们所处的阶段，可以避免把“生成成功”“抠图完成”或“网页能打开”误当成正式交付。

## 建议阶段

1. **概念与方案图**：用于选择故事、姿势和构图。
2. **已选关键帧**：角色、姿势、道具和首尾关系已经确认，可作为视频输入。
3. **原始视频候选**：检查动作、构图、镜头、人体结构和背景干净程度。
4. **已确认原片**：原始动作获视觉认可，可进入透明处理和合成。
5. **透明人物层**：检查 alpha、描边、半透明区域和画布边缘。
6. **完整合成**：人物、SVG 效果和调色形成最终视觉候选。
7. **已锁定资产**：用户确认视觉结果，来源和处理记录完整。
8. **运行时集成**：状态映射、循环次数、尺寸、速度和 host 交互通过实际运行检查。
9. **已发布版本**：按目标仓库或部署渠道完成发布并读取真实结果。

阶段名称可以按项目调整；关键是不要用同一个“完成”同时表示多种交付物。

## 验收边界

- 图片获选，只说明可以作为关键帧；
- 原片获选，只说明动作值得继续加工；
- 透明层通过，只说明抠图合格；
- 完整合成通过，才说明最终视觉合格；
- 本地预览通过，不证明运行时或线上部署已更新；
- 文件存在、静态截图或 HTTP 成功响应不能代替连续播放验收。

这些是验收边界，不是要求机械地重复询问用户。用户已经明确授权一个连续批次时，应在该范围内继续完成；只有新增付费生成、扩大方案范围、部署发布或改变已选方向等超出既有授权的动作，才需要新的决定。

## 可追溯记录

按项目需要记录：

- 输入图片的角色和哈希；
- 提示词与生成请求；
- 原始任务或来源标识；
- 片段关系和共同关键帧；
- 用户选定的版本与播放速度；
- 抠图、调色和矢量合成方法；
- 最终运行时引用的文件。

不要把 API key、个人路径、私有部署地址或无复用权的原始素材写进公开仓库。

## 文件管理

- 保留已确认阶段的输入和处理记录，避免覆盖；
- 新尝试使用清楚的版本或实验目录；
- 跑偏方案可以归档，是否保留由项目需求决定；
- 原始大媒体是否提交由目标仓库政策决定，不自动加入版本控制；
- 部署和发布是独立动作，完成后应读取真实目标验证。
